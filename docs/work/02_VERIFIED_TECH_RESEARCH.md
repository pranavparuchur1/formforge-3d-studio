# Verified technology and competitor research

Research cutoff/access date: 2026-10-27, America/New_York. Official documentation and publisher release pages were retrieved through web research. Unless a publication date is given, no stable update date was exposed. Access date is not a publication date. Product claims below are vendor-documented, not hands-on competitor tests. No account, purchase or competitor editor session was used.

No current prices or plan entitlements were verified, so none are used to justify a pricing advantage. Vectary's marketing and export documentation differ in breadth; treat detailed export support as documented capability subject to plan/version verification, not a tested entitlement. The old starter's exact Spline “October 19 MCP” claim is unnecessary for the product decision and is not adopted as verified. [Spline changelog](https://spline.design/changelog) was reviewed, but current agent documentation is the direct evidence for competitive overlap.

Recommended validation: five beginner task sessions, including familiarity with alternatives, willingness to keep projects locally, and whether readable build plans help learning. Positioning is provisional until these sessions. A useful MVP can be small without claiming that competitors lack the same individual features.

Observed candidate tuple for a later isolated compatibility PR: React/React DOM 19.3.1, Fiber 9.8.1, Drei 10.7.9, Three 0.180.0 retained first, Vite 8.3.5, Playwright 1.64.1. This tuple has **not** been installed or browser-tested. No production lockfile is delivered. Exact TypeScript, React plugin, Zustand, Node patch, FastAPI and backend transitive pins remain implementation gates, not invented versions. Do not install “latest” blindly or use --force/--legacy-peer-deps to suppress incompatibility.

At that PR run `npm view <package>@<candidate> version peerDependencies engines license --json`, install exact direct versions, commit package-lock.json, run `npm ls`, `npm ci`, build, typecheck, unit and browser tests. Record resolved transitive tree and audit. For backend, use a fresh Python 3.12 environment, resolve/pin hashes, run `pip check`, `pip-audit` and schema/API tests. The broad Node 20+ starter guidance is insufficient for current Vite. [Official Node release status](https://nodejs.org/en/about/previous-releases) lists Node 24 as LTS at access time.

## Security findings from research

The official [Vite advisory index](https://github.com/vitejs/vite/security/advisories) lists recent dev-server issues. [GHSA-rq7h-c2jc-7f22](https://github.com/vitejs/vite/security/advisories/GHSA-rq7h-c2jc-7f22), published 2026-10-06, describes conditional file exposure; patches include 8.3.3, 8.2.4, 8.1.6, 7.3.7 and 6.4.4. [GHSA-8g5g-mxqh-grgj](https://github.com/vitejs/vite/security/advisories/GHSA-8g5g-mxqh-grgj), published 2026-10-21, affects 6.4.4 and is patched in 6.4.5. These illustrate why an old starter pin or generic “Vite is secure” assertion is inadequate. Bind development to loopback; deploy built static files rather than a dev/preview server.

[FastAPI advisories](https://github.com/fastapi/fastapi/security/advisories) and [Pydantic advisories](https://github.com/pydantic/pydantic/security/advisories) were reviewed; historical entries do not certify today's full dependency graph. Three's advisory page retrieval failed. No lockfile exists, so no meaningful complete npm/pip vulnerability audit was run. Release requires scanning the chosen lockfile including development tooling and reviewing applicable advisories for React, Three, loaders, Starlette and Pydantic-core. No “zero vulnerabilities” conclusion is supported.

## Accessibility and portability basis

[WCAG 2.2](https://www.w3.org/TR/WCAG22/) (Recommendation update 2024-12-12) and [new criteria guidance](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/) support non-drag alternatives, usable target sizes and visible focus. Apply these as product requirements, then test keyboard and assistive technology; a canvas label alone is not accessible modeling. GLB geometry/material numeric parity matters more than identical lighting across viewers. See 03 and 05 for exact operational criteria.
